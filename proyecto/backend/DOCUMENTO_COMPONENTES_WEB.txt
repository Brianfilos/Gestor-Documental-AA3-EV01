   Descripción del Proyecto:
   ─────────────────────────
   El Sistema Gestor Documental es una aplicación web desarrollada con el
   framework Django que permite la gestión integral de documentos digitales
   dentro de una organización. Incluye funcionalidades de autenticación de
   usuarios, gestión de roles y permisos, carga y administración de archivos,
   clasificación documental, sistema de revisiones y un registro histórico
   completo de todas las operaciones realizadas.

   Tecnologías Frontend Utilizadas:
   ─────────────────────────────────
   • Lenguaje de marcado   : HTML5
   • Estilos visuales      : CSS3 (personalizado) + Bootstrap 5.3.2
   • Iconografía           : Bootstrap Icons 1.11.x
   • Motor de plantillas   : Django Template Language (DTL)
   • Interactividad        : JavaScript (vanilla, integrado en plantillas)

   Módulos Principales del Sistema:
   ─────────────────────────────────
   • Autenticación y control de sesión
   • Panel de control (Dashboard) con estadísticas
   • Gestión de documentos (CRUD completo)
   • Clasificación de documentos
   • Historial de actividad
   • Gestión de usuarios y roles
   • API REST para integración con aplicación móvil Android

   INTRODUCCIÓN
   ════════════

   En el contexto actual de la transformación digital, la gestión eficiente de
   documentos se convierte en un pilar fundamental para el funcionamiento de
   cualquier organización. Los procesos manuales de archivo y consulta de
   documentos físicos presentan problemas de tiempo, seguridad y trazabilidad
   que impactan negativamente la productividad institucional.

   El presente documento especifica la arquitectura y estructura de componentes
   de la interfaz web del Sistema Gestor Documental, una solución de software
   desarrollada con Django 4.2 en el backend y Bootstrap 5 en el frontend.
   Esta aplicación centraliza la gestión de documentos digitales, permitiendo
   a los usuarios con diferentes roles (Administrador, Editor, Revisor,
   Visualizador) interactuar con el sistema de forma segura y controlada.

   La interfaz web está construida mediante el sistema de plantillas de Django
   (Django Template Language), que permite la reutilización de componentes y
   la separación clara entre la lógica de negocio y la presentación visual.
   Todas las vistas están diseñadas con un enfoque "mobile-first" gracias a
   Bootstrap 5, garantizando accesibilidad desde diferentes dispositivos.

   La arquitectura de componentes sigue el patrón MVT (Modelo - Vista -
   Plantilla) propio de Django:

   • MODELO    : Define la estructura de datos en models.py (Documento,
                 Usuario, Clasificación, Historial, Revisión).
   • VISTA     : Contiene la lógica de procesamiento en views.py, devuelve
                 los datos a las plantillas mediante contextos.
   • PLANTILLA : Archivos HTML ubicados en la carpeta /templates/ que
                 renderizan la interfaz de usuario.

   Este documento se centra específicamente en la capa de PLANTILLAS (parte
   web/frontend), describiendo cada componente HTML, su función dentro del
   sistema, los elementos utilizados y el código principal de cada archivo.

   El sistema cuenta con los siguientes archivos de plantilla organizados en
   dos módulos principales:

   │  Módulo Usuarios              │  Módulo Documentos                     │

   │  • usuarios/login.html        │  • templates/documentos/detalle.html    │
   │  • usuarios/dashboard.html    │  • templates/documentos/formulario.html │

                    PÁGINA 4 - DEFINICIÓN DE ELEMENTOS HTML A UTILIZAR
================================================================================

   DEFINICIÓN DE ELEMENTOS HTML UTILIZADOS EN EL DISEÑO FRONTEND
   ══════════════════════════════════════════════════════════════

   A continuación se definen todos los elementos HTML5 utilizados en el diseño
   de las interfaces del Sistema Gestor Documental, organizados por categoría:

   ────────────────────────────────────────────────────────────────────────────
   4.1 ELEMENTOS DE ESTRUCTURA Y SEMÁNTICA (HTML5)
   ────────────────────────────────────────────────────────────────────────────

   <!DOCTYPE html>
   Declaración del tipo de documento. Indica al navegador que el documento
   sigue el estándar HTML5. Presente en base.html como raíz de todas las
   plantillas.
   Uso en proyecto: Primera línea de base.html.

   <html lang="es">
   Elemento raíz del documento HTML. El atributo lang="es" indica al
   navegador y tecnologías de asistencia que el contenido está en español,
   mejorando la accesibilidad y el SEO.
   Uso en proyecto: base.html - define el idioma de toda la aplicación.

   <head>
   Contenedor de metadatos del documento. No es visible para el usuario pero
   contiene información esencial: charset, viewport, título, enlaces a CSS.
   Uso en proyecto: base.html - incluye Bootstrap 5 y Bootstrap Icons.

   <meta charset="UTF-8">
   Define la codificación de caracteres del documento. UTF-8 soporta todos
   los caracteres del español (tildes, ñ) y caracteres especiales.
   Uso en proyecto: base.html - garantiza correcta visualización en español.

   <meta name="viewport" content="width=device-width, initial-scale=1.0">
   Configura el viewport para diseño responsivo. Sin este meta, las páginas
   se verían como versiones de escritorio en móviles.
   Uso en proyecto: base.html - habilita el diseño responsivo con Bootstrap.

   <title>
   Define el título del documento que aparece en la pestaña del navegador
   y en los resultados de búsqueda.
   Uso en proyecto: base.html con bloque DTL - {% block title %}GestorDoc{% endblock %}

   <body>
   Contenedor del contenido visible de la página. En el proyecto tiene la
   clase "d-flex" de Bootstrap para el layout sidebar + contenido principal.
   Uso en proyecto: base.html - estructura el layout general de la app.

   <header>
   Elemento semántico que representa la cabecera de la página o sección.
   Uso en proyecto: base.html - contiene la barra superior con título y acciones.

   <nav>
   Elemento semántico para bloques de navegación principal. Contiene los
   enlaces de menú del sistema.
   Uso en proyecto: base.html - sidebar de navegación lateral.

   <main>
   Elemento semántico que representa el contenido principal del documento.
   Solo debe haber uno por página.
   Uso en proyecto: base.html - área donde se inserta el contenido de cada vista.

   <section>
   Elemento semántico genérico para agrupar contenido temáticamente
   relacionado dentro de la página.
   Uso en proyecto: dashboard.html - sección de estadísticas, sección de tabla.

   <article>
   Elemento semántico para contenido independiente y auto-contenido.
   Uso en proyecto: detalle.html - ficha de documento, sección de revisiones.

   <footer>
   Elemento semántico para el pie del documento o sección.
   Uso en proyecto: Incluido en base.html para información del sistema.

   <aside>
   Elemento semántico para contenido relacionado pero separado del principal.
   Uso en proyecto: detalle.html - panel lateral del historial del documento.

   ────────────────────────────────────────────────────────────────────────────
   4.2 ELEMENTOS DE TEXTO Y CONTENIDO
   ────────────────────────────────────────────────────────────────────────────

   <h1> a <h6>
   Encabezados de nivel 1 al 6 que definen la jerarquía del contenido.
   Uso en proyecto:
   • <h1>: Logo "GestorDoc" en el sidebar (base.html)
   • <h5>: Título de tarjetas y modales
   • <h6>: Subtítulos dentro de secciones

   <p>
   Párrafo de texto. Elemento de bloque básico para texto descriptivo.
   Uso en proyecto: Descripción de documentos, mensajes de estado vacío,
   textos informativos en el dashboard.

   <span>
   Elemento de línea genérico para agrupar texto en línea y aplicar estilos.
   Uso en proyecto: Badges de estado (activo, inactivo, revisión, archivado),
   iconos de Bootstrap Icons dentro de botones.

   <strong>
   Indica texto de gran importancia (renderizado en negrita). Semánticamente
   diferente a <b> ya que implica relevancia.
   Uso en proyecto: Labels de datos en la ficha del documento.

   <small>
   Representa texto de menor importancia, como notas al pie o comentarios.
   Uso en proyecto: Fechas secundarias, información adicional de usuario.

   <a>
   Hipervínculo para navegar entre páginas o secciones del sistema.
   Atributos principales: href (destino), class (estilos Bootstrap).
   Uso en proyecto: Todos los enlaces de navegación del sidebar, botones de
   acción en tablas (ver, editar), enlace de descarga de documentos.

   ────────────────────────────────────────────────────────────────────────────
   4.3 ELEMENTOS DE FORMULARIO
   ────────────────────────────────────────────────────────────────────────────

   <form>
   Contenedor principal de un formulario HTML. Define el método de envío
   (GET o POST) y la acción (URL destino).
   Atributos clave:
   • method="post"      : Envío seguro de datos (login, crear, editar)
   • enctype="multipart/form-data" : Necesario para subir archivos (documentos)
   • action=""          : Envía al mismo URL actual
   Uso en proyecto:
   • login.html       : Formulario de autenticación (método POST)
   • formulario.html  : Crear/editar documento con carga de archivo
   • usuarios/formulario.html : Crear/editar usuario
   • detalle.html     : Formulario de revisión/comentario
   • clasificacion_form.html : Crear/editar clasificación

   {% csrf_token %}
   Token de seguridad de Django (renderiza un <input type="hidden">) que
   protege los formularios contra ataques CSRF (Cross-Site Request Forgery).
   Uso en proyecto: Obligatorio en TODOS los formularios POST del sistema.

   <input type="text">
   Campo de texto de una línea para entrada de datos cortos.
   Uso en proyecto:
   • login.html      : Campo de correo electrónico (con type="email")
   • formulario.html : Campo "Título del documento"
   • lista.html      : Campo de búsqueda con placeholder="Buscar documentos..."

   <input type="email">
   Campo de texto especializado para direcciones de correo electrónico.
   El navegador valida automáticamente el formato del email.
   Uso en proyecto: login.html y usuarios/formulario.html para el correo.

   <input type="password">
   Campo de texto que oculta los caracteres escritos con asteriscos/puntos.
   Uso en proyecto: login.html - contraseña de acceso al sistema.

   <input type="file">
   Permite al usuario seleccionar un archivo de su dispositivo para subirlo.
   Atributo accept=".pdf,.doc,.docx,.xls,.xlsx" restringe tipos permitidos.
   Uso en proyecto: formulario.html - carga del archivo del documento.

   <input type="hidden">
   Campo invisible para el usuario que transmite datos al servidor.
   Uso en proyecto: csrf_token y campos de relación en formularios Django.

   <input type="checkbox">
   Casilla de verificación para opciones binarias (sí/no).
   Uso en proyecto: Selector de estado activo/inactivo en formulario de usuario.

   <textarea>
   Campo de texto multilínea para texto extenso.
   Atributos: rows (número de filas visibles), cols, placeholder.
   Uso en proyecto:
   • formulario.html : Campo "Descripción" del documento (rows="4")
   • detalle.html    : Campo de comentario para revisiones (rows="3")
   • clasificacion_form.html : Descripción de la clasificación

   <select>
   Lista desplegable para seleccionar una opción entre varias predefinidas.
   Uso en proyecto:
   • formulario.html : Selector de "Estado" del documento
                       (activo / inactivo / revision / archivado)
   • formulario.html : Selector de "Clasificación" del documento
   • lista.html      : Filtros de búsqueda por estado y clasificación
   • usuarios/formulario.html : Selector de "Rol" del usuario

   <option>
   Define una opción dentro de un elemento <select>.
   Atributo value: valor enviado al servidor al seleccionar la opción.
   Uso en proyecto: Dentro de todos los <select> del sistema.

   <optgroup>
   Agrupa opciones dentro de un <select> con una etiqueta descriptiva.
   Uso en proyecto: Agrupación de estados en selectores de filtro.

   <label>
   Etiqueta descriptiva asociada a un control de formulario.
   El atributo for debe coincidir con el id del input asociado.
   Mejora la accesibilidad y la usabilidad (clic en label activa el input).
   Uso en proyecto: Todas las etiquetas de campos en formularios del sistema.

   <button>
   Botón interactivo para ejecutar acciones dentro de un formulario o página.
   Tipos: type="submit" (envía formulario), type="button" (acción JS),
          type="reset" (limpia el formulario).
   Uso en proyecto:
   • Botón "Iniciar Sesión" en login
   • Botón "Guardar" en formularios de creación/edición
   • Botón "Eliminar" en páginas de confirmación
   • Botón de toggle para mostrar/ocultar contraseña (login)
   • Botón "Filtrar" y "Limpiar" en lista de documentos

   <fieldset>
   Agrupa visualmente controles de formulario relacionados.
   Atributo disabled: desactiva todos los controles dentro del grupo.
   Uso en proyecto: Agrupación de campos en formularios extensos.

   <legend>
   Título descriptivo para un elemento <fieldset>.
   Uso en proyecto: Título de grupos de campos en formularios.

   ────────────────────────────────────────────────────────────────────────────
   4.4 ELEMENTOS DE TABLA
   ────────────────────────────────────────────────────────────────────────────

   <table>
   Define una tabla de datos. En el proyecto se usa con clase Bootstrap
   "table table-hover table-striped" para estilos modernos.
   Uso en proyecto: lista.html (documentos), usuarios/lista.html (usuarios),
   historial.html (registro de actividad), dashboard.html (documentos recientes).

   <thead>
   Agrupa las filas del encabezado de la tabla. Semánticamente separa
   la cabecera del cuerpo y el pie de la tabla.
   Uso en proyecto: Encabezados de todas las tablas del sistema.

   <tbody>
   Agrupa las filas de datos del cuerpo de la tabla.
   Uso en proyecto: Contenido de todas las tablas del sistema.

   <tr>
   Define una fila (row) dentro de una tabla.
   Uso en proyecto: Cada documento, usuario o registro de historial es una <tr>.

   <th>
   Define una celda de encabezado dentro de <thead>.
   Atributo scope="col" mejora la accesibilidad de lectores de pantalla.
   Uso en proyecto: ID, Título, Clasificación, Estado, Fecha, Acciones.

   <td>
   Define una celda de datos dentro de <tbody>.
   Uso en proyecto: Valores de cada campo en cada fila de las tablas.

   <caption>
   Proporciona un título o descripción accesible para la tabla.
   Uso en proyecto: No implementado actualmente (mejora futura recomendada).

   ────────────────────────────────────────────────────────────────────────────
   4.5 ELEMENTOS DE LISTA
   ────────────────────────────────────────────────────────────────────────────

   <ul>
   Lista desordenada (sin numeración). Con Bootstrap: clase "list-unstyled"
   elimina los puntos y el padding.
   Uso en proyecto: Lista de enlaces del sidebar en base.html,
   lista de revisiones en detalle.html.

   <ol>
   Lista ordenada (numerada).
   Uso en proyecto: No usado directamente pero implementable en historial.

   <li>
   Elemento de lista, contenido de <ul> o <ol>.
   Uso en proyecto: Cada enlace de navegación del sidebar, cada revisión.

   <dl>
   Lista de definiciones: términos y sus descripciones.
   Uso en proyecto: Metadatos del documento en detalle.html
   (etiqueta: valor como "Clasificación: Técnico").

   <dt>
   Término en una lista de definiciones.
   Uso en proyecto: Labels de datos del documento (Clasificación, Estado, etc).

   <dd>
   Descripción del término en una lista de definiciones.
   Uso en proyecto: Valores de los metadatos del documento.

   ────────────────────────────────────────────────────────────────────────────
   4.6 ELEMENTOS DE MEDIOS E INTEGRACIÓN
   ────────────────────────────────────────────────────────────────────────────

   <img>
   Inserta una imagen en el documento.
   Atributos: src (ruta), alt (texto alternativo accesible), width, height.
   Uso en proyecto: Logo del sistema en sidebar, avatares de usuario con
   iconos de Bootstrap Icons como imágenes de perfil SVG.

   <i>
   Elemento de texto en cursiva, reutilizado por Bootstrap Icons para
   mostrar íconos vectoriales mediante clases CSS.
   Uso en proyecto: Iconos en toda la aplicación:
   • bi-file-earmark-text : Icono de documentos
   • bi-people-fill       : Icono de usuarios
   • bi-clock-history     : Icono de historial
   • bi-grid-1x2-fill     : Icono de dashboard
   • bi-tags-fill         : Icono de clasificaciones
   • bi-eye               : Ver documento
   • bi-pencil            : Editar
   • bi-trash             : Eliminar
   • bi-download          : Descargar archivo
   • bi-plus-circle       : Agregar nuevo
   • bi-box-arrow-right   : Cerrar sesión
   • bi-person-circle     : Perfil de usuario

   <iframe>
   Embebe un documento HTML dentro del actual. No utilizado en este proyecto
   pero relevante para futura previsualización de PDFs en el navegador.

   ────────────────────────────────────────────────────────────────────────────
   4.7 ELEMENTOS DE AGRUPACIÓN Y LAYOUT
   ────────────────────────────────────────────────────────────────────────────

   <div>
   Elemento de bloque genérico para agrupar contenido y aplicar estilos.
   Es el elemento más utilizado junto con las clases de Bootstrap 5 para
   construir el layout del sistema.
   Uso en proyecto (clases Bootstrap más frecuentes):
   • div.container-fluid    : Contenedor a ancho completo
   • div.row               : Fila del sistema de grilla Bootstrap
   • div.col-md-4 col-lg-3 : Columnas responsivas (4 cols / 12 en pantalla MD)
   • div.card              : Tarjeta con borde y sombra
   • div.card-body         : Cuerpo interno de la tarjeta
   • div.card-header       : Encabezado de la tarjeta
   • div.alert             : Mensajes de alerta/notificación
   • div.modal             : Ventana modal superpuesta
   • div.d-flex            : Contenedor flex (flexbox)
   • div.sidebar           : Barra lateral de navegación (custom)
   • div.main-content      : Área de contenido principal (custom)

   <span>
   Elemento de línea genérico para agrupar texto en línea y aplicar estilos.
   Uso en proyecto:
   • Badges de estado: <span class="badge bg-success">Activo</span>
   • Contadores numéricos en el dashboard
   • Iconos inline dentro de botones

   <hr>
   Línea horizontal de separación temática.
   Uso en proyecto: Separador entre secciones del sidebar y del formulario.

   <br>
   Salto de línea. Usado con moderación para separación visual.
   Uso en proyecto: Espaciado entre elementos en páginas de confirmación.

   ────────────────────────────────────────────────────────────────────────────
   4.8 ELEMENTOS DE SCRIPTING Y RECURSOS EXTERNOS
   ────────────────────────────────────────────────────────────────────────────

   <script>
   Incluye o define código JavaScript en el documento HTML.
   Uso en proyecto:
   • Inclusión de Bootstrap Bundle JS (con Popper.js incluido)
   • Toggle de visibilidad de contraseña en login
   • Auto-cierre de alertas después de 3 segundos
   • Inicialización de tooltips de Bootstrap

   <link>
   Vincula recursos externos al documento HTML (principalmente CSS).
   Uso en proyecto:
   • Bootstrap 5.3.2 CSS (CDN)
   • Bootstrap Icons CSS (CDN)
   • Estilos personalizados inline en <style>

   <style>
   Bloque de CSS inline dentro del documento HTML.
   Uso en proyecto: Estilos personalizados del sidebar, stat-cards, badges
   de estado, responsive overrides, definidos en base.html.

   ────────────────────────────────────────────────────────────────────────────
   4.9 ATRIBUTOS HTML GLOBALES RELEVANTES
   ────────────────────────────────────────────────────────────────────────────

   id
   Identificador único del elemento en el documento. Utilizado para:
   • Anclas de navegación
   • Asociación label-input (for=id)
   • Selección desde JavaScript
   • Targets de modales Bootstrap
   Ejemplo: <input id="correo" name="correo" type="email">

   class
   Asigna una o más clases CSS al elemento. El uso de clases Bootstrap 5
   elimina la necesidad de CSS personalizado extenso.
   Ejemplo: <button class="btn btn-primary d-flex align-items-center gap-2">

   name
   Nombre del campo en formularios, usado como clave al enviar datos al server.
   Ejemplo: <input name="titulo"> → request.POST["titulo"] en Django view.

   placeholder
   Texto de guía dentro de inputs de formulario cuando están vacíos.
   Ejemplo: <input placeholder="Buscar por título o descripción...">

   required
   Atributo booleano que hace obligatorio un campo de formulario.
   El navegador impide el envío si el campo está vacío.
   Uso en proyecto: Campos obligatorios en todos los formularios.

   disabled
   Atributo booleano que desactiva un elemento de formulario.
   Uso en proyecto: Botones durante carga, campos de solo lectura.

   data-*
   Atributos personalizados para almacenar datos en elementos HTML.
   Uso en proyecto: data-bs-toggle="modal", data-bs-target="#confirmModal"
   para activar modales de Bootstrap.

   action
   En <form>: URL a la que se envían los datos del formulario.
   En el proyecto generalmente vacío (envía al mismo URL).

   method
   En <form>: Método HTTP de envío (GET para filtros, POST para escritura).

   enctype
   En <form>: Tipo de codificación. "multipart/form-data" requerido para
   subir archivos.

   href
   En <a>: URL de destino del enlace.
   Uso en proyecto: URLs de Django generadas con {% url 'nombre_url' %}.

   target="_blank"
   En <a>: Abre el enlace en una nueva pestaña/ventana.
   Uso en proyecto: Enlace de descarga/visualización de documentos.

   download
   En <a>: Indica que el recurso debe descargarse en lugar de abrirse.
   Uso en proyecto: Botón "Descargar" en la ficha del documento.

   type
   En <button>: Define el comportamiento (submit, button, reset).
   En <input>: Define el tipo de campo (text, email, password, file, hidden).

   value
   En <input>/<option>: Valor enviado al servidor cuando el elemento
   es seleccionado o enviado.

   7.3 CLASES CSS PERSONALIZADAS DEL SISTEMA
   ────────────────────────────────────────────────────────────────────────────

   .sidebar
   Barra lateral fija de 260px de ancho. Gradiente vertical de #0D47A1 a
   #1976D2. Posición fixed en pantallas grandes, se colapsa en móviles.

   .sidebar-brand
   Contenedor del logo "GestorDoc" en el sidebar. Fondo ligeramente más
   oscuro, tipografía grande y en negrita.

   .sidebar-nav li a
   Enlace de navegación del sidebar. Texto blanco, relleno interno cómodo,
   esquinas redondeadas. En hover: fondo #1E88E5. Íconos con margen derecho.

   .nav-section-title
   Etiqueta de sección dentro del sidebar (ej: "PRINCIPAL", "CONFIGURACIÓN").
   Texto en mayúsculas, tamaño pequeño, color semitransparente.

   .main-content
   Área de contenido principal. Ocupa el espacio restante (flex-grow-1).
   Fondo gris claro #F8F9FA. Scroll independiente del sidebar.

   .top-bar
   Barra superior fija dentro del main-content. Fondo blanco, sombra suave.
   Contiene el título de la página y botones de acción principales.

   .stat-card
   Tarjeta de estadística del dashboard. Fondo blanco, borde izquierdo
   coloreado (4px solid), sombra suave, icono grande, valor numérico prominente.

   .table-card
   Contenedor de tablas de datos. Fondo blanco, borde redondeado, sombra
   suave, header con fondo gris claro y texto en negrita.

   .badge-activo     → background: #198754 (verde Bootstrap success)
   .badge-inactivo   → background: #6C757D (gris Bootstrap secondary)
   .badge-revision   → background: #FFC107 (amarillo Bootstrap warning)
   .badge-archivado  → background: #0DCAF0 (cian Bootstrap info)

   ────────────────────────────────────────────────────────────────────────────
   7.4 TIPOGRAFÍA
   ────────────────────────────────────────────────────────────────────────────

   Fuente principal  : Sistema (system-ui, -apple-system, sans-serif)
                       Bootstrap 5 usa la fuente nativa del sistema operativo
                       garantizando máxima legibilidad y rendimiento.

   Tamaños utilizados:
   • Títulos de página    : 1.25rem (h5 Bootstrap)
   • Texto del sidebar    : 0.9rem
   • Etiquetas de sección : 0.7rem (uppercase, semitransparente)
   • Valores estadísticas : 2rem (font-weight: 700)
   • Texto de tablas      : 0.875rem (table-sm Bootstrap)
   • Badges de estado     : 0.75rem

   ────────────────────────────────────────────────────────────────────────────
   7.5 SISTEMA DE GRILLA (Bootstrap 5 Grid)
   ────────────────────────────────────────────────────────────────────────────

   El sistema utiliza la grilla de 12 columnas de Bootstrap 5 con los
   siguientes breakpoints:

   BREAKPOINT    PREFIJO    ANCHO MÍNIMO    USO EN EL SISTEMA
   ─────────────────────────────────────────────────────────────────────────
   Extra Small   (ninguno)  < 576px         Móviles: columnas apiladas
   Small         sm         ≥ 576px         Tablets pequeñas
   Medium        md         ≥ 768px         Tablets: formularios 2 columnas
   Large         lg         ≥ 992px         Escritorio: layout completo
   Extra Large   xl         ≥ 1200px        Pantallas grandes
   ─────────────────────────────────────────────────────────────────────────

   Distribuciones de columna más usadas en el proyecto:
   • col-md-3  : Tarjetas de estadísticas en dashboard (4 por fila en MD+)
   • col-md-4  : Campo de búsqueda en filtros de lista de documentos
   • col-md-8  : Área principal del formulario de documento
   • col-md-4  : Sidebar del formulario (clasificación, estado, archivo)
